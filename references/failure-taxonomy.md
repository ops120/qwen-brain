# 失败分类与恢复动作

`qwb` 的所有失败都是可枚举的：`{ok:false, reason, message?, retryAfterMs?}`。
按下表处理；需要用户介入时**一次只给一个动作**。

| reason | 含义 | 动作 | 对用户说 |
| --- | --- | --- | --- |
| `HUMAN_VERIFICATION_REQUIRED` | 阿里滑块验证未在时限内完成 | 停；让用户在浏览器完成拖动后重试；或加大 `--captcha-wait` | 「千问弹了滑块验证，请在浏览器里拖一下。」 |
| `LOGIN_REQUIRED` | 需要登录（仅显式跑了 `login` 却没完成时） | 千问匿名可用；不登录直接用 `ask` 即可 | 「没登录也没关系，匿名模式能用；想解锁生图 / 生视频再登录。」 |
| `RATE_LIMITED` | 限流 / 额度用尽（游客模式额度低） | 停，按 `retryAfterMs` 退避；游客模式被限时可建议登录 | 「额度到顶了，等一会再试；登录可以拿更多额度。」 |
| `COMPOSER_NOT_FOUND` | 输入框定位失败 | `doctor --deep`；多半是改版 → 按 `SITE_CHANGED` | 不要把 DOM 细节讲给用户 |
| `SITE_CHANGED` | 选择器漂移 | **版本问题**：`doctor --deep` 定位；告知维护者修 `scripts/qwb/src/site.mjs` 并发版。不要现场硬试 DOM | 「千问页面改版了，需要更新 qwen-brain。」 |
| `SEND_FAILED` | 发送 / 注入失败 | 重试一次；仍失败按 `SITE_CHANGED` | — |
| `STREAM_STALLED` | 流式停滞 / 超时 | 已捕获内容标注「可能截断」；思考研究模式耗时长是正常的，先查是否给了足 `--timeout` | 「回答可能不完整。」 |
| `UPLOAD_REJECTED` | 附件被拒 | 检查类型 / 大小（限制由千问网页端决定） | 「这个文件网页版收不了，换一个或压缩后再试。」 |
| `THREAD_LOST` | 会话 404 / 丢失 | 新会话重问；`[QWB]` 模式则从 checkpoint 发 HANDOFF | — |
| `LOCKED` | 另一任务占用浏览器 | 等；或问用户是否停掉另一个任务 | 「有另一个任务正在使用千问浏览器。」 |
| `DEPENDENCY_MISSING` | 依赖缺失 | 自愈：`setup` | — |
| `SENSITIVE_BLOCKED` | 闸门拦截 | 移除敏感内容或改用摘要；确需发送必须用户明确同意 | 「内容里含敏感信息，已被拦截；需要你确认才能发送。」 |
| `PAYLOAD_TOO_LARGE` | 正文超过 50 KB | 先摘要或分片；确需整段加 `--allow-large` | 「内容太长，我先压缩一下再发。」 |

## 硬规则

- **绝不**把失败伪装成结果；**绝不**静默降级后不告知
  （模式没切换成功必须标注 `modes.mode` 与请求值的差异）。
- **绝不**为绕过失败去手工操作 DOM——机制只存在于 CLI。
- **绝不**尝试自动滑动滑块验证码——那是风控红线，必须用户本人完成。
- 重试有上限：同类失败最多 2 次，之后交用户或上报维护者。
- 思考研究模式耗时 1–3 分钟是**正常**的，不要因为慢就判失败。
